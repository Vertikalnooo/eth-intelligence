# EI-CAP-3 PostgreSQL authorization core — offline research
Scope: implement A02/A03 subset of Cloud-Native v2; no cloud changes, bootstrap, live transport, or migration. Schema has no initial rows or LOGIN roles. Explicit disposable test fixture creates state and random keys only. ei2 is unchanged. Actual PG17 server required; official signed PGDG package installation on disposable CI runner only if absent. Tests inside existing loopback-only namespace. Existing runner may also have PG18; new suite explicitly selects /usr/lib/postgresql/17/bin and asserts server_version_num.

Wire refinement: 24 ordered ASCII fields (see ei_cap3.py), length decimal followed by ":" and exact bytes, concatenated with no delimiters. Added next_owner_head and prior_authorization to bind before/after journal and chain. All numerics are canonical decimal strings <= 2^53-1. Environment OFFLINE, scope SYNTHETIC_ONLY; version EI-CAP-3. Domain strings EI-CAP-3/TRUST and EI-CAP-3/WITNESS followed by LF and frame. Different 32-byte HMAC keys pinned by key epoch. PostgreSQL reconstructs frame from text[] (not JSON) and validates exact bytes, rejects unknown field count/NULL/shape/oversize/noncanonical values. Python and JavaScript pure frame encoders, no network or signing API; test fixture computes tags independently. Raw incoming JSON duplicate-key detection belongs to future Gateway, not this object encoding.

SQL state machine: READY -> ARMED -> ISSUED -> PENDING -> CLOSED -> ADVANCED; UNKNOWN -> FROZEN. ARM requires fresh plan/epoch/grant and cooldown. ISSUE/CONSUME enforce one grant and 120-second expiry. Each op advances checkpoint, prior authorization, journal head, two sequence counters; credential revision increments exactly once for ARM/ISSUE/CONSUME/ADVANCE and remains unchanged for terminal actions. Terminal digest must match ADVANCE; terminal attestations are synthetic fixture evidence, not proof of market fetch. 30-second maximum capability lifetime, strict not-before/expiry after row lock, no grace beyond expiry, 900-second cooldown. Both MACs computed and compared inside DB, fixed 32 iterations (not formally constant time; timing acceptance pending). No DENY after mutation: state/grant/spent checkpoint and event written atomically or transaction abort. No runtime reset, key read, arbitrary SQL function, generic signing oracle. Audit role reads state/event/grant/used-checkpoint metadata only. Role wrappers require exact session_user and op; NOLOGIN until explicit provisioning, private schema and function ACL, fixed search path. Fixture revokes PUBLIC database CREATE/TEMP and public schema CREATE; on real Neon validate those database-wide ACLs and inherited memberships separately before provisioning, do not apply these changes now. Extension install deliberately fails if already installed elsewhere; future migration must inspect extension owner/schema/ACL rather than relocate blindly.

Critical limits: a DB function cannot force caller transaction commit or prevent rollback, and SET synchronous_commit in the function does not guarantee caller's commit setting after return. A pre-commit OK is not authorization to fetch. External independent committed-state audit and verifier spend-before-release are mandatory; broker must use synchronous commit at session and commit acknowledgement. A malicious broker may rollback or set async commit. Replay after transaction rollback or database restore with still-valid capability is possible until expiry; test documents rollback versus durable committed replay. Quarantine/revoke old logins, TTL drain and key epoch rotation are separate acceptance gates. DB administrator has both keys; compromised broker with already valid dual capability can use it once after commit; no prevention of arbitrary egress. No formal constant-time claim. WebAuthn, independent verifier issuance, receipt provenance, external pins, and cloud TLS remain pending. No ADVANCED cache release or external transport implemented. Stage 2 OPEN, recommendation_eligible=false.
